# 潛力幣雷達

登入後從導覽列的「潛力幣雷達」進入 `/potential-radar`。此功能保存公開現貨量價與研究紀錄，不會下單；Worker 已配置既有 Slack 權杖和頻道時，會通知新合格候選，未設定時只更新畫面。

## 第一版範圍

- 動態取得 Bybit 當前可交易的 USDT 現貨交易對，不依賴原本固定 45 檔名單。已知穩定幣、黃金代幣與名稱可識別的槓桿代幣排除；此分類仍需隨市場維護。
- 初篩要求交易所近 24 小時成交額至少 500 萬 USDT，買賣價差不超過 0.3%。十二個候選名額由四檔漲幅、四檔成交額與輪替探索組成，另保留一檔歷史追蹤。
- 每檔一次取得最多 1000 根 15 分線，使用交易所原始 USDT 成交額。聚合時只保留 UTC 對齊且完整的 1 小時與 4 小時 K 線，不混用交易所。
- 每側中間價上下 1% 內、最多 50 檔掛單深度至少 1 萬 USDT，才可入榜。掛單可能撤回，不代表保證成交。
- 每輪現貨先使用 Bybit，整輪失敗才切換 Gate；BTC、標的成交量與深度始終鎖定同所，不跨所拼接。既有波段雷達的多來源備援保持原狀。
- 這是候選輪替掃描，並非全市場每 15 分鐘完整重算，也不含鏈上新發行代幣、社群情緒、市值或解鎖資料。前三個優先候選會另取 Gate 永續公開統計作風險確認。

## 訊號規則

所有門檻均為待樣本外驗證的假設，目前入選版本為 `15m-v4-derivatives`（舊紀錄保留先前版本）。量價分數算法未改，分數是符合程度，不是機率。

| 分類 | 條件 |
| --- | --- |
| 提前關注 | 距前 16 根高點不超過 1 ATR、尚未突破、15 分價格上升且近 1 小時強於 BTC；成交額至少前 20 根均值 2 倍，或近期收斂且至少 1.3 倍 |
| 剛啟動 | 15 分收盤突破前 16 根高點，成交額至少前 20 根均值 2 倍 |
| 回踩續強 | 前 16 根內曾放量突破，後續收盤守住原突破位，當根回踩後站上前根高點且量能至少 1.2 倍 |
| 漲幅過熱 | 收盤距突破位超過 1.5 ATR，或近 24 小時上漲超過 30%；不列優先榜 |
| 等待條件／不合格 | 未形成訊號或流動性不合格；不列優先榜 |

ATR 採最近 14 根真實波幅的簡單平均。整理收斂使用前 80 個二十根布林帶寬度的低 20% 門檻，前八根曾觸及即成立，沒有使用當根擴張判斷先前收斂。

1h／4h 趨勢均要求最新完整週期收盤高於 MA20 且 MA20 上升。352 根 15 分歷史可涵蓋所需完整 4h 暖機；較新的幣暫不評分。BTC 比較使用同時刻 1h、4h、24h 報酬差，並顯示 BTC 下跌與「跌得較少」風險。

分數：量能 25、相對 BTC 25、結構 25、1h／4h 趨勢 15、整理 10。流動性不合格直接歸零。結構失效參考是最近四根低點，不是實際停損委託。

## 研究追蹤

### 吃大魚策略 2.0（15 分線）

沿用提供的 Pine Script 實際條件，計算模組為 `app/services/potentialRadar/bigFish.ts`，訊號版本為 `big-fish-2.0-15m-v1`：

- **提早進場**：MACD（12、26、9）當根金叉，且收盤嚴格高於 EMA200 × 0.98。前根 MACD 等於訊號線也可構成交叉；持續在線上不重複觸發。
- **確認進場**：Supertrend（ATR 10、係數 4）由紅轉綠，方向由 1 變成 -1。此分支不要求 MACD 金叉或 EMA200 條件。
- **原始進場**：上述任一條件成立；僅檢查最新已收盤的 15 分 K 線，下一根不沿用事件。ATR 使用 Wilder RMA（首十根以 SMA 初始化），EMA 使用首根收盤種子。
- **多單出場條件**：ST 方向為紅色時成立；雷達沒有持倉資料，因此顯示「若持有多單」的提示，不宣稱已平倉。提早金叉可能在紅色趨勢中出現，畫面會同時呈現進出場條件。
- 提供的 Pine 程式沒有實作「獲利 3% 後移至保本」；也沒有額外的 `close < st` 判斷，這次不補入未存在的交易規則。

「吃大魚進場」分類呈現原始觸發，包含被流動性或過熱條件排除者；合格的新觸發即使量價階段仍是「等待條件」，也可進入「優先觀察」。量價分類與五項分數保持原樣，卡片另列吃大魚原因、ST 防守線、EMA200 及 MACD 數值。

訊號沿用同一輪的 Bybit／Gate 現貨資料，不新增行情請求。不同交易所、取得的歷史起點、EMA／ATR 暖機長度及盤中／收盤時點，可能使結果與 TradingView 不完全一致；本次未以完整同源 TradingView 歷史逐根比對，也未驗證策略勝率。

新欄位保存在既有快照及研究 JSON，不需新增 migration。舊紀錄顯示尚未計算；下次新版排程成功掃描才會更新。研究仍沿用每幣 24 小時間隔，因此不會保存每次吃大魚觸發，也不是持倉回測。

本機每分鐘重新載入目前掃描模組，成功去重同時檢查 K 線時間與策略版本。升級前的成功摘要不能擋住新版補算；失敗後也不會被本機時間格快取永久略過。波段與潛力幣排程各自防重疊，某一雷達行情緩慢不會阻塞另一個。收盤後前兩分鐘仍等待交易所資料，不把上一根訊號冒充當根。

### 中週期趨勢共振

吃大魚與量價分類維持原本的 15 分候選邏輯；新增的共振是第二層確認與排序，不會把短線原始觸發改寫成不存在。

- **4h MA20 回踩轉強**：MA20 必須上升，最近兩根 4h K 線需回到 MA20 加半個 ATR 的支撐帶，最新 4h 收盤站回 MA20 且突破前根高點，才標示「已確認回踩轉強」。缺少 21 根完整 4h K 線時顯示歷史不足。
- **日線 MA7 向上**：最新完整日線收盤高於 MA7，且 MA7 高於前一根日線的 MA7。雷達現有 15 分歷史最多約十天，故採 MA7；不足八根完整日線時標為「資料不足」，不當作反向趨勢。
- 只有兩項同時成立才是「趨勢共振」。共振候選在畫面最前方並可用「趨勢共振」分類查看；未確認的原始候選仍保留，可用於研究比對。
- 計算只聚合同一來源已收盤的 15 分資料，不增加外部 API 請求，因此不會讓輪替掃描變慢。

### Gate 永續籌碼確認

- 每輪先依趨勢共振、吃大魚事件及量價分數排序，只替前三個合格候選抓取 Gate USDT 永續資料。每檔使用約 75 分鐘 OI／多空／清算統計及近 31 天最多 100 筆資金費率；不需要 API key。
- **健康趨勢**：現貨近 1h 至少上漲 0.4%，OI 至少增加 0.75%，且未同時達到費率與多空比擁擠條件。
- **軋空上漲**：現貨近 1h 至少上漲 0.4%，OI 至少下降 0.75%。**新增空單**是價格下跌且 OI 增加；**去槓桿**是價格與 OI 同跌。
- **多頭擁擠**：價格與 OI 同漲，正資金費率位於自身近期第 90 百分位以上，且大戶或帳戶多空比至少 1.35。這些都是第一版研究門檻，需由下方分類績效重新校準。
- 永續資料缺少合約、統計不足 45 分鐘或暫時失敗時，保留原現貨候選並標示資料不足；不得把缺值當成 OI 零變化，也不因衍生品服務失敗讓整輪榜單消失。
- 分類與原始數值一起保存在既有快照及研究 JSON，無需新增 migration。它只作風險提示，不改寫吃大魚、趨勢共振或量價進場條件。

### Slack 候選通知

- 僅在已收盤的 15 分線首次從非候選進入「趨勢共振」合格候選時通知；已在候選中的幣不會每輪重送。若「吃大魚進場」在新根 K 線觸發，且同時通過趨勢共振，即使該幣已在候選清單，也會另發一次。
- 流動性不合格或漲幅過熱的標的不能發送通知。訊息包含來源、收盤時間、價格、量能、Gate 永續籌碼、訊號依據、結構失效參考與風控提示；不包含下單指令或勝率宣稱。
- 快照和待發事件會一起寫進 D1 的 `potential_radar_notifications` 佇列。Slack 暫時失敗、限流或逾時時不標記已送，後續排程每輪最多補送三則；超過一根 15 分 K 的補送會標示為歷史事件。
- Slack 接收後若回應中斷，系統為了避免漏報可能重送，因此無法保證跨系統恰好一次。已成功的通知保留 30 天後清理。
- 本機開發雷達刻意不傳入 Slack 權杖或頻道，只掃描及更新本機畫面，不會實際發送測試訊息。

### 追蹤規則

- 每幣首次合格入選後保存原始訊號、分數版本、收盤參考價及實際發現時間，至少間隔 24 小時才建立下一筆樣本；最新卡片持續更新。
- 追蹤 24h、72h、7 天收盤報酬，以及入選收盤之後、最多七天的最大上漲／最大下跌。排除入選當根高低，避免引用發現前的整根波動。
- 研究基準是入選 K 線收盤，不是排程發現時的可成交價；未扣手續費、滑價，不是策略回測或交易績效。
- 歷史補算採輪替，最長讀取最近八天未完成的樣本。若退市、缺行情或八天內未補齊，保留失敗紀錄；缺失值不當成零報酬，也不宣稱已完成。
- 首頁只列最新 100 筆研究紀錄，資料庫保留更早紀錄。下方條件績效是描述性統計，不視為已驗證勝率；目前也未做漲幅榜／成交額榜的樣本外比較。

### 條件績效

- 頁面使用同一批最近 100 筆入選紀錄，比較原始訊號，以及永續健康趨勢、軋空、多頭擁擠、空方／去槓桿分類。條件可能重疊，各列樣本數不可相加。
- 24h、72h、7 天平均報酬與正報酬率各自只使用已成熟且非空的固定時間收盤報酬，畫面顯示每個指標的實際分母；未到期資料不當成 0。
- 1R 是入選收盤到當時結構失效價的距離。只有七天完整、追蹤無錯誤且結構失效價有效的樣本進入分母；七天內最大漲幅達到 1R 即視為達標。
- 最差回撤只使用七天完整且無缺口的樣本。數據未扣手續費與滑價，近期 100 筆也可能受行情階段與候選選擇影響，不代表已驗證勝率。

## 排程與啟用

1. 使用 Node.js v20.19.6 或較新的 v20.x。
2. 套用至 `drizzle/0014_potential_radar_notifications.sql`（包含先前 migration）。本機使用 `npm run db:migrate:local`；正式環境使用 `npm run db:migrate:remote`，需沿用既有發布流程及權限。
3. 建置與部署應用程式；`wrangler.toml` 已設定 `POTENTIAL_RADAR_ENABLED = "true"`。如要啟用通知，正式 Worker 另需既有的 `SLACK_API_TOKEN` 與 `SLACK_CHANNEL_ID` secret；不得把實際值寫進版本控制。
4. 確認新增 cron `2,17,32,47 * * * *` 已在 Cloudflare 生效；每個 15 分收盤後兩分鐘獨立執行。可把環境變數設為 `false` 停止新掃描，歷史紀錄仍可讀取。
5. 登入頁面檢查最近完成時間、成功／失敗數，以及實際來源可用性。

租約為十分鐘，掃描預算五分鐘。最多 35 個行情請求；快照與觀察採多列 SQL 寫入，單句最多 90 個研究參數，完整寫入在同一 D1 batch 中。最大負載測試驗證行情請求加 SQL 數不超過 50。故障輪次不自動擴大重試量，下一輪重試。

```sh
node --import tsx --test tests/potential-radar*.test.ts
npm run build
npx wrangler deploy --dry-run
```

開發驗證使用合成行情與暫存 D1，未變更正式資料庫或部署。初版環境的公開 API 連線檢查回報 `fetch failed`，正式機房可用性仍須上線驗證。
