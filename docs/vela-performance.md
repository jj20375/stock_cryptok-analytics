# Vela 首頁圖表效能改善

2026-10-06 使用合成行情，在同一個瀏覽器內比較相同的 500 根 K 線、640 個線段與 72 個訊號。以下是當時使用合併路徑的版本量測；後續價格縮放補正改用批次原生線段，尚未重新量測此表數值。

| 項目 | 原接法 | 批次資料圖層 |
| --- | ---: | ---: |
| 同步提交策略圖層 | 3570.1 ms | 2.0 ms |
| 至後續兩個畫格完成 | 4109.7 ms | 25.1 ms |
| 系統建立的互動繪圖物件 | 712 | 0 |

這是此次本機瀏覽器單次對照，用來定位圖層更新瓶頸，不是所有裝置的效能保證，也不包含下載、API 查詢或整頁載入時間。

## 原因

先前將自動策略線段當成使用者手動畫線：每次更新刪除整組線段，再逐筆新增與鎖定。Vela 的互動繪圖 API 會在這些操作保存撤銷歷史、序列化整個繪圖集合並同步至 renderer。數百個線段產生大量重複複製及同步。

行情更新另會同時進入資料 effect 與圖層 effect，重做兩次策略繪製。這是我們原本的接法造成的可改善負擔。

## 修正

- 系統策略改用 Vela 原生指標的資料輸出，一次提交線條與圖示，不建立互動繪圖或加入撤銷歷史。
- 策略線維持原始端點、色彩與斷點，以原生線段一次提交，避免長路徑拉大價格縮放。
- 同一次 React 更新的行情及圖層變更合併，資料完成載入後才繪製最新策略。
- 策略圖示、時間軸說明、圖層開關保留，個別圖表卸載時解除原生指標註冊。

## 檢查

- 三項回歸測試：線條連續與斷點、多訊號及原因保留、圖表實例隔離與清理。
- 以完整首頁元件載入 500 根合成行情，驗證切換商品、隱藏／顯示策略與縮放。瀏覽器沒有新增錯誤。
- `npm run build` 通過。Vela workspace 主區塊約 1.13 MB（gzip 約 323 KB），共享核心另約 136 KB（gzip 約 33 KB），兩者合計仍約 1.27 MB（gzip 約 356 KB），首次載入仍比 KLineCharts 大；此次修正針對互動更新停頓。

目前保留 Vela。若真實使用仍明顯吃資源，可依使用者已授權的方向改回既有 KLineCharts；不需要先移除回測使用中的 KLineCharts 套件。

## 成交量與開關補正（2026-10-06）

後續檢查實際首頁資料傳遞時，發現 `MainChartPanel` 將全部策略送到 Vela，因此按鈕狀態雖更新，圖表仍顯示停用策略。現在控制列保留全部策略，圖表只接收啟用項目；這補正了先前預覽未涵蓋實際父元件傳入全部策略的情境。

- 明確建立原生 Volume 指標，待 `ready` 後移到價格圖下方的獨立副圖，紅漲綠跌。
- 策略控制列改成精簡排列，顯示「開／關」狀態及獨立「全開／全關」按鈕，支援鍵盤與輔助工具。
- 以 `MainChartPanel` 載入 220 根合成行情，確認全關移除策略線與訊號、VOL 仍保留，單獨開啟吃大魚只恢復該策略。瀏覽器無錯誤或警告。
- 建置通過；完整 TypeScript 檢查仍有既有四項錯誤（Freqtrade 的 D1 型別與兩個根目錄／scratch 腳本），本次修改未新增錯誤。

本次補正已部署，版本 `254c6438-53c1-4301-a8fc-9ffdafb3a556`。

## K 線顯示高度補正（2026-10-06）

Vela 0.8.1 的 polyline 自動縮放只要路徑時間範圍與視窗相交，就把所有端點價格納入；先前合併的長策略線因此將畫面外的歷史低價也算入，壓扁近期 K 線。改用批次原生 `lines`，只讓相交的個別線段參與縮放，保留全部線條與顏色，不加入互動繪圖或撤銷歷史。

以 500 根合成行情（早期約 1,000、近期約 2,500）確認近期視窗刻度不再被早期低價拉大，VOL 與其他副圖仍保留。預覽首次啟動遇到 Vite 重新預打包的重複模組錯誤，重新載入後畫面與策略線正常，無新增錯誤。`npm run build` 通過。

縮放補正已部署，版本 `b4b518f1-91df-4a8d-8479-32aa0b860a0e`。
