# 玄學羅盤（紫微變盤時機＋八字個人運勢）設計文件

- 日期：2026-11-09
- 狀態：設計已確認，待撰寫實作計畫
- 範圍：新增獨立的「玄學羅盤」功能，不改動任何既有量化訊號

## 1. 目標與定位

1. 用**紫微斗數市場本命盤**推算台股、BTC、美股的「變盤時機」與方向傾向。
2. 依登入者的**八字**分析命局、投資性格、大運流年財運、流月流日吉凶。
3. 把市場變盤日與個人流日吉凶疊在同一張日曆上，提供「玄學參考」。
4. 用歷史行情**回測命中率**並與「任意一天」的基準機率並列，讓使用者自行判斷準不準。

### 不做的事（硬性邊界）

- **不寫入**台股漲跌羅盤分數、策略選股、自動下單、風控或任何既有排程。
- **不推播**（不新增排程、不發 Slack／Telegram）。等命中率累積後再另行決定。
- **不給個股買賣指令**。輸出只到運勢層級的描述（例如「宜守」「財星受剋」「順勢」）。
- 第一版不做真太陽時（出生地經度校正）、不處理從格與調候、不做五行對應產業。

## 2. 技術選型

| 用途 | 套件 | 說明 |
|---|---|---|
| 紫微排盤與運限四化 | `iztro`（MIT，v2.6.x） | 純 JS，可在 Cloudflare Worker 執行 |
| 八字、節氣、農曆 | `lunar-typescript`（MIT） | iztro 本身已依賴，不另外多一套曆法庫 |
| 解盤文字潤飾 | 既有 `app/services/aiService.ts` 的 `getAIResponse` | 沿用專案 AI 設定 |

不採用外部玄學 API（生辰會外流、結果不可控），也不自己實作安星規則（規則上百條，出錯風險高）。

**規劃時實測後的調整**：iztro 單次排運限約 5ms，頁面要算 3 市場 × 31 天，Worker CPU 負擔太重。因此改成：

- 三個市場的本命盤用 iztro **預先產生**成常數檔（`marketNatalCharts.generated.ts`），iztro 只當 devDependency，Worker 執行期不載入。
- 執行期只用 lunar-typescript 算流年、流月、流日天干，再查四化表（每天約 0.01ms）。流月以農曆月＋五虎遁計算，閏月 16 日起算下個月，已與 iztro 逐日比對 2015–2026 共 12 年完全一致；四化表也與 iztro 一致。
- lunar-typescript 打包後約 340KB（minified）。

## 5. 紫微變盤規則（`RULE_VERSION = 'ziwei-v1'`）

### 5.1 計算流程

對每個市場的每個交易日：

1. 取當天的流年、流月、流日天干，查出對應的化祿、化權、化科、化忌星曜。
2. 找出這些星曜在市場本命盤中所落的宮位。
3. 只看「關鍵宮位」：命宮、財帛宮、官祿宮、田宅宮、福德宮、遷移宮。
4. 依層級加權：流日 1.0、流月 0.6、流年 0.3。

### 5.2 方向分數（-100～+100）

| 事件 | 基礎分 |
|---|---|
| 化祿入關鍵宮位 | +20 |
| 化權入關鍵宮位 | +10 |
| 化科入關鍵宮位 | +5 |
| 化忌入關鍵宮位 | -20 |
| 化忌入關鍵宮位的對宮（沖） | -15 |

方向分數 = Σ(基礎分 × 層級權重)，四捨五入後夾在 -100～+100。

### 5.3 變盤強度（0～3）

先累加變盤點數，再對應強度：

| 事件 | 點數 |
|---|---|
| 流日化忌入命宮或財帛宮 | +2 |
| 流日化忌沖命宮或財帛宮 | +2 |
| 忌星疊併：流日化忌與流年或流月化忌**同宮** | +2 |
| 祿忌同宮：**流日**化祿所在宮有任一層化忌，或**流日**化忌所在宮有任一層化祿 | +1 |
| 流日化權入命宮或遷移宮 | +1 |

點數 0–2 → 強度 0；3 → 1；4 → 2；5 以上 → 3。

> **2026-11-09 規劃時修正（依觸發頻率校準，未看任何行情）**：原版規則（疊併含互沖、祿忌同宮不限層級、1 點即強度 1）在 2016–2025 年逐日試算時，三個市場有 33–58% 的日子被標為強度 ≥ 2，變盤標記失去意義。修正後強度 ≥ 2 的比例為台股約 20%、BTC 約 14%、美股約 8%。這次校準只看規則自身的觸發頻率，沒有對照任何漲跌資料，不構成對行情的擬合。

### 5.4 防止過度擬合

- 上述權重與門檻在跑回測**之前**就固定為 v1。
- 任何調整都必須升版 `RULE_VERSION`，報告要並列新舊版本，並註明「看過回測才調整的規則有過度擬合風險」。
- 每個結果都附上觸發的規則清單（`triggers`），頁面可以展開查看。

## 6. 八字規則（`RULE_VERSION = 'bazi-v1'`）

### 6.1 命局基礎（`baziProfile.ts`）

- **四柱**：由 lunar-typescript 依節氣排出（年柱以立春為界，月柱以節為界）。
- **日主強弱**：三項計分。
  - 得令：月令五行與日主相同或生日主 +3，其他 0。
  - 得地：四個地支中，藏干本氣為比劫或印者各 +1；中氣或餘氣為比劫或印者各 +0.5（同一地支最多計 1 分）。
  - 得勢：其他天干中每個比劫或印 +1。
  - 總分 ≥ 5 為身強，≤ 2 為身弱，其餘為中和。
- **喜用神（扶抑法簡化版）**：身弱喜印、比劫；身強喜財、官殺、食傷；中和以財、食傷為喜。不處理從格與調候，頁面要註明是簡化版。
- **投資性格標籤**（可同時有多個，依十神出現次數與是否透干）：

| 條件 | 標籤 |
|---|---|
| 偏財透干或兩個以上 | 機會型：善抓短線、資金進出快 |
| 正財為主、無偏財 | 穩健型：適合長期持有、紀律分批 |
| 比劫重（三個以上） | 從眾型：易跟風、與人爭財 |
| 食傷生財（食傷與財並見） | 研究型：靠分析與判斷獲利 |
| 七殺透干 | 冒險型：風險承受度高、易重押 |
| 身弱財多 | 財多身弱：機會多但守不住，宜控倉 |

### 6.2 運勢（`baziLuck.ts`）

- **大運、流年**：干支五行與喜用神相同或相生為吉，與喜用神相剋為凶，其餘為平。另外標記兩個特徵：財星出現且身能任財 → 「財運佳」；比劫奪財 → 「破財風險」。
- **流月、流日**：用同一套評分，輸出五級：大吉、吉、平、凶、大凶。流日地支沖日支時加註「變動」。
- 時辰不明時只用年、月、日三柱計算。

### 6.3 疊加提示（`combinedHint.ts`）

| 市場變盤強度 | 個人流日 | 提示 |
|---|---|---|
| ≥ 2 | 凶、大凶 | 宜守：市場易變盤，你今天財星受剋 |
| ≥ 2 | 吉、大吉 | 動中有機：市場易變盤，你今天運勢偏順 |
| ≤ 1 | 吉、大吉 | 順勢：盤勢平穩，你今天運勢偏順 |
| ≤ 1 | 凶、大凶 | 少動：盤勢平穩，但你今天不宜衝動 |
| 其他 | 平 | 平常心 |

提示一律是運勢描述，不包含標的或買賣動作。

## 7. 時間處理（`calendarTime.ts`）

- **子時換日**：23:00 起算隔天的日柱（台灣命理常見做法），設定頁與結果頁都要註明。
- **台灣舊日光節約時間**：內建 1945–1979 年台灣實施日光節約時間的年份與起訖日期對照表；出生時間落在區間內時，排盤前先減 1 小時。這張表要附上資料來源註解，並逐年寫成測試。
- **市場交易日**：流日依各市場時區的當地日期；非交易日（週末、休市）在日曆上照樣顯示玄學結果，但不列入命中率計算。
- 伺服器端一律用明確的時區換算，不依賴執行環境的系統時區。

## 9. 資料流

### 頁面載入（`/metaphysics` loader）

1. 確認已登入（沿用 `app/utils/auth.ts`），未登入導向登入頁。
2. 對三個市場算「今天＋未來 30 天」的紫微結果（純函式，不需快取）。
3. 今天的結果若還沒寫入 `metaphysics_market_forecasts`，就寫入快照（不覆寫既有快照）。
4. 回填快照中已收盤、但 `actual_change_pct` 為空的日期（透過 marketData 取日 K）。
5. 讀取並解密使用者生辰；有資料就算八字命局、大運流年、未來 30 天流日與疊加提示。
6. AI 解說：先查快取，沒有才呼叫 AI。呼叫有逾時限制，並與頁面主體分開載入，避免拖慢頁面。
7. 命中率：讀取回測結果（見第 10 節）＋線上快照統計。

### 設定頁儲存生辰

表單驗證日期合法（含農曆閏月）→ 加密 → upsert `user_birth_profiles`。提供「刪除我的生辰資料」按鈕。

### 送給 AI 的內容（隱私）

只送規則層算出的**衍生標籤**：身強或身弱、喜用五行、十神性格標籤、大運流年與流日吉凶等級、觸發規則。**不送**出生年月日時，也不送四柱干支（四柱可以反推出生日期）。

## 10. 命中率與回測

### 定義（`hitRate.ts`）

- **實際變盤**：當日漲跌幅絕對值 ≥ 前 20 個交易日平均漲跌幅絕對值 × 1.5，或前 3 個交易日**連續同向**而當日反向。（只看前 3 日累計方向的話，約一半的日子都算反轉，基準機率會失真。）
- **變盤命中率**：在變盤強度 ≥ 2 的日子中，實際變盤的比例。
- **基準機率**：同期間所有交易日中，實際變盤的比例。
- **方向命中率**：在方向分數絕對值 ≥ 30 的日子中，分數正負號與實際漲跌一致的比例；基準為同期間「一直猜漲」的命中率。
- 每個比例都附樣本數與 95% Wilson 信賴區間；玄學命中率的區間與基準區間重疊時，標示「與隨機無明顯差異」。

### 回測腳本 `scripts/backtest-ziwei-timing.ts`

- 資料遵守既有回測資料鐵則：台股 `^TWII`、美股 `^GSPC` 走 `stockDailyHistory`（Yahoo），BTC 走 `binanceHistory`（2017-08 起），以 `kline_cache` 為唯一真相來源；不得使用 `stockService.fetchStockData()`。
- 期間：台股與美股用 Yahoo `range=20y` 的日線（約 2006 年底起；實測 `range=max` 只回月線，不能用），BTC 自資料來源可取得的最早日期起。報告要寫出實際起訖日期。
- 輸出 Markdown 報告與 SQL 檔（`output/metaphysics/` 下）。報告包含各市場、各強度等級的命中率與基準對照；SQL 檔用 `wrangler d1 execute --file` 匯入 D1 的 `metaphysics_market_forecasts`（`source = 'backtest'`），供頁面計算命中率。腳本本身不連 D1。
- 上線後的每日快照：台股與美股只在週一至週五建立，BTC 每天建立；休市日沒有行情可回填，該列維持空值，不計入命中率。
- 頁面上「回測命中率」（`source = 'backtest'`）與「上線後快照命中率」（`source = 'live'`）分開顯示。

## 12. 錯誤處理

| 狀況 | 處理 |
|---|---|
| 時辰不明 | 八字只排三柱；紫微個人盤不排（本設計的紫微只用市場盤，不受影響）；頁面提示補填時辰可得完整分析 |
| 未填生辰 | 「我的八字」分頁與首頁小卡顯示引導 |
| 生辰解密失敗 | 視同未填，`console.error` 記錄，不讓頁面崩潰 |
| AI 失敗或逾時 | 改用規則模板文字；不寫入快取，下次重試 |
| 行情抓不到 | 命中率標示「資料不足」，不補假資料；快照的實際漲跌維持為空，下次再回填 |
| iztro／lunar 例外（例如日期超出支援範圍） | 該日顯示「無法排盤」，其他日期照常 |

## 13. 測試

測試放在 `tests/`，沿用既有測試框架。

- **排盤正確性**：以 iztro 與 lunar 官方文件的範例命盤、數組公開人物八字作為比對資料。
- **邊界**：立春前後的年柱、節氣交界的月柱、23:00 子時換日、農曆閏月、台灣日光節約時間逐年驗證。
- **紫微規則**：用人工指定的四化落宮輸入，驗證方向分數、變盤點數與強度對應。
- **八字規則**：日主強弱計分、喜用神、性格標籤、吉凶等級的單元測試。
- **命中率**：用人工造的 K 線驗證變盤判定、基準機率與 Wilson 區間。
- **加密存取**：生辰加密後寫入、讀取解密一致；錯誤金鑰視同未填。
- **AI fallback**：模擬 AI 拋錯時回傳模板文字且不寫快取。
